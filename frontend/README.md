# HerbKyoor Ayurveda — Migrated Frontend (static HTML + CSS + JS)

The public site is **pure static HTML5 + CSS3 + vanilla JavaScript** — no Node.js,
no React, no Next.js, no PHP required to view it, and **no build step on the host**.
Upload the contents of this `frontend/` folder to any web host (including plain
shared/static hosting) via FTP.

PHP is used **only** for the backend/API (admin writes + form handlers), which is a
separate later phase — see the repo-root `API_REQUIREMENTS.md`. Companion doc:
`MIGRATION_ANALYSIS.md`.

---

## How it works
- Every public page is a static `.html` file. Shared **header/footer/floating
  WhatsApp** are generated by JS (`js/components.js` + `js/layout.js`) and injected
  into `#site-header` / `#site-footer` placeholders — written once, reused everywhere.
- Product/category data is loaded with the **Fetch API** through a small data layer
  (`js/api.js` → `window.Data.*`). By default it reads the bundled JSON snapshot in
  `/data`; flip one flag to read the PHP API instead (see **Data source** below).
- Design is preserved by a **compile-once Tailwind** bundle: `css/style.css` is the
  committed, minified output of `css/tailwind-input.css` (theme tokens copied from
  the original app). The host never builds anything.
- Interactivity is vanilla JS: instant search/filter/sort/pagination (`products.js`),
  carousels (`carousel.js`), scroll-reveal (`reveal.js`), gallery + quantity +
  WhatsApp order links (`product-details.js`), nav (`main.js`), forms
  (`contact.js`, `newsletter.js`).
- The **admin** panel (`admin/`) is a static HTML SPA that talks to the PHP admin API
  (built in the backend phase).

## Data source (dev vs production)
`js/config.js`:
```js
USE_STATIC_DATA: true,      // read /data/*.json (works with zero backend)
STATIC_DATA_BASE: "/data",
API_BASE_URL: "/api",       // used when USE_STATIC_DATA = false, and for writes
```
- **As shipped** (`true`): the whole storefront works on plain static hosting.
- **With the PHP backend** (`false`): reads `GET /api/products/list.php` etc. per
  `API_REQUIREMENTS.md`. Admin + contact/newsletter always POST to `/api/...`.

## Run locally — IMPORTANT: use a server, not `file://`
The site loads data with the Fetch API, which browsers block on `file://`. **Open
it through a web server**, not by double-clicking the HTML file:
```bash
cd frontend
python3 -m http.server 8100        # or: npx serve, php -S 127.0.0.1:8100, VS Code Live Server…
# open http://127.0.0.1:8100/index.html
```
> If you open `index.html` directly (`file://…`) the page will look **unstyled and
> empty** — that's the Fetch/asset restriction, not a bug.

### Paths are relative (works at any base)
All asset/link references (`css/…`, `js/…`, `assets/…`, `data/…`, page links) are
**relative**, so the site works whether it's served from the web root, a subfolder,
or an IDE Live Server rooted anywhere. If you previously saw missing CSS, it was an
absolute-path issue — now fixed. (Only the backend `API_BASE_URL` and the SEO
`canonical`/`og:image` URLs are absolute; adjust `API_BASE_URL` in `js/config.js`
if your PHP API isn't at the site's `/api`.)

## Recompile CSS (only if you change markup/classes)
```bash
npx @tailwindcss/cli@4 -i frontend/css/tailwind-input.css -o frontend/css/style.css --minify
```
`@source` globs in `tailwind-input.css` scan all `.html` + `.js`.

## Regenerate the data snapshot
`data/products.json`, `categories.json`, `testimonials.json`, `advertisements.json`
are generated from `data/Product_list.json`. In production the PHP backend serves
this data live; the JSON snapshot is the static fallback. Regenerate with a small
script (Node/PHP) that reproduces the normalization documented in
`API_REQUIREMENTS.md` (§A) — or let the backend own it.

## Deploy (FTP)
1. (If markup changed) recompile `css/style.css` locally.
2. Upload the entire `frontend/` directory to your web root.
3. Update `SITE_URL` / phone / email in `js/config.js`, and the `Sitemap:` line in
   `robots.txt`, to your real domain. Regenerate `sitemap.xml` for the real domain.
4. `.htaccess` sets `DirectoryIndex index.html`, the `/404.html` error page, caching
   and gzip. (Optional — the site also works without it.)

```
frontend/
├── index.html  products.html  product-details.html
├── about.html  contact.html   privacy-policy.html  terms.html  404.html
├── robots.txt  sitemap.xml  .htaccess

├── js/            config, icons, utils, api (Data layer), components, layout,

│                  contact, newsletter

│                  advertisements.json  Product_list.json (source)

```

## Security
- No database credentials or secrets anywhere in the frontend (`js/config.js` holds
  only public config).
- All writes go through the authenticated PHP admin API (backend phase).
